## 先理解我们做了什么

想象一个透明盒子，里面有 108 个会互相推拉的小球。计算机根据力学规律，每次推进一小段时间，计算小球的新位置和速度。这就是这里的分子动力学模拟。

盒子使用“周期边界”：球从右侧出去，会从左侧回来，像一些游戏中的地图。盒子不是硬墙，小球不会在边上反弹。

课程作业已经提供了模拟和动画。你的 Final 在这个基础上回答两个问题：

1. **哪个粒子运动得快？** 每个球按速率着色：蓝色慢、红色快。色条固定在 0–4，超过 4 都显示红色。
2. **一个粒子走过哪里？** 给编号 0 的球加白色标记，显示它最近 1,000 个模拟步的路径。

这里的编号 0 是数组里的第一个粒子，不是一种特殊原子。颜色表示速率，不表示单个粒子的温度。

## 第一次运行：15 分钟

1. 双击项目文件夹中的 `run_demo.cmd`。
2. 观察彩色小球，按空格暂停。
3. 暂停时按 C，比较统一颜色和速度着色。
4. 按 T，比较显示轨迹和隐藏轨迹。
5. 按方向键旋转，看白色标记及轨迹。
6. 再按空格继续，最后按 Esc 退出。

程序跑到 3,000 步后会停在最后一帧，此时仍可旋转或切换显示。它没有卡死。按 Esc 会正常保存输出。

如果窗口一闪而过，请从 PowerShell 运行 `run_demo.ps1` 阅读报错。若缺少可执行文件，先按 README 的方法编译；这台电脑已完成编译。OpenGL 窗口需要本机显卡驱动支持。

## 再看懂三个关键概念：30 分钟

**位置**：用 x、y、z 表示粒子在盒子中的位置。代码中是 `r[i][0..2]`。

**速度与速率**：`rv[i][0..2]` 是三个方向的速度分量。颜色使用速率，也就是速度向量的长度：`sqrt(vx² + vy² + vz²)`。

**模拟步与画面帧**：一个模拟步推进时间 0.005。默认每 10 步显示一帧，但轨迹在每一步都采样，所以记录不受画面帧率影响。最后 1,000 个样本的首尾时间跨度为 999 个步长。

单位使用 Lennard-Jones 约化单位，不能直接说“每秒多少米”或“多少开尔文”。项目没有指定映射到现实材料的单位参数。

## 为什么边界不能直接连线？

假设盒子长度为 10。粒子的位置从 9.9 变成 0.1，实际只是跨过边界移动了一小段。如果直接画线，就会错误地从 9.9 连到 0.1，横穿整个盒子。

我们的处理是：相邻位置在任一方向相差超过半个盒子，就在这里断开轨迹。程序还检查每步真实位移小于半盒长，保证这个判断适用于当前运行。没有画出盒子外的展开轨迹，也没有计算扩散系数。

## 按这个顺序读代码：约 1 小时

1. `src/visualization.h`：看 `particle_speed` 和 `speed_color`，理解速度如何变成颜色。
2. 同一文件的 `Trail`、`trail_add`：理解为什么只保留最近 1,000 个位置。
3. `trail_connect`：理解跨边界时为什么不连线。
4. `src/md_visualizer.c` 的 `events`：对应刚刚按过的键。
5. `observe_step`、`properties`：看数据如何被观察和记录，而不修改运动状态。
6. `render`：把颜色、球和轨迹画出来。
7. 最后看 `original/md.c` 的 `SingleStep`：知道它用已有的速度-Verlet方法更新运动即可，不需要先推导整套公式。

## 怎么证明这个程序可信？

我们另写了一个不使用显示功能的参考运行器，直接调用保存下来的原始模拟代码。比较结果：

- 3,000 步后，108 个粒子的位置与速度输出完全一致。
- 包括初始状态的 3,001 个能量数据逐项一致。
- 四种颜色／轨迹开关组合的数值结果一致。
- 暂停时位置、速度、步数和历史不变。
- 已知的边界跨越例子不会产生假连线。

这证明“我们增加了观察方式，但没有改变这次模拟的计算结果”。它不代表证明了所有参数下的物理正确性，也不是模拟变快了。
